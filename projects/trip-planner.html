Trip Planner

A resilient planning workspace for a 32-day Nepal and Japan journey, designed around unreliable networks, shared decisions, and information that must remain useful on the move.

The challenge

Travel planning becomes a systems problem when the plan spans two countries, many cities, multiple people, and unreliable networks. A usable solution has to preserve context, work on phones, and avoid turning every feature into a cloud dependency.

Product shape

  • Local-first planning: itinerary changes and core trip state remain usable on the device.
  • Offline delivery: a service worker precaches the application shell and surfaces updates instead of silently refreshing.
  • Optional synchronization: Firebase mirrors trip data when configured while the application remains functional without it.
  • Real geographic context: MapLibre renders destinations, categories, popups, and itinerary overlays without a paid map key.

Engineering decisions

The application is a Next.js static export so it can ship to GitHub Pages. Photos use IndexedDB, lighter preferences stay local, and capability-scoped trip sharing keeps collaboration explicit.

The interface supports keyboard navigation, reduced motion, small-screen layouts, and a command palette because travel tools are often used quickly and under imperfect conditions.

Evidence

The release pipeline validates repository hygiene and versioning before publishing. Firestore rules are tested against the real local rules engine across eleven phases, including signed-out, member, owner, and stranger behavior.

The live product is public and installable, making the work directly inspectable rather than a design-only prototype.
