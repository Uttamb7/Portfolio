E-Store Footware

A role-aware footwear store that separates customer buying flows from administrative inventory operations across a testable three-tier system.

View source ↗Back to portfolio
The specific problem

Customer browsing, cart, and checkout behavior must coexist with administrator inventory controls without mixing permissions or business logic.

Team
5 engineers
Backend
Java + Spring
Frontend
Angular + TypeScript
Design
3 explicit tiers
Technology

The challenge

The store had to coordinate product discovery, cart state, checkout, inventory mutation, and order visibility while keeping customer and administrator responsibilities distinct.

As a five-person academic team, the additional challenge was creating boundaries clear enough for parallel implementation and integration.

Architecture

  • Angular presentation: customer and administrator views own interaction and client-side state.
  • Spring REST layer: controllers expose explicit workflows instead of leaking persistence details.
  • Domain models: product, cart, user, and order behavior stays separate from transport concerns.
  • DAO persistence: repository contracts isolate the JSON-backed data implementation.

Verification

The Maven build supports controller, model, and persistence test tiers in isolation or together, plus JaCoCo HTML coverage reporting. The project portfolio reports more than 75 tests and 96 percent code coverage.

Acceptance criteria and generated design documentation gave the team a shared definition of behavior beyond the code itself.

What it proves

E-Store is not presented as production commerce infrastructure. Its value is the engineering discipline behind a full-stack team delivery: role-aware workflows, explicit layers, repeatable tests, and clear ownership boundaries.
