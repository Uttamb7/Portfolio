Tiny Transformer

A GPT-style language model built from first principles to inspect tokenization, causal attention, training stability, evaluation, and scaling rather than hide them behind a hosted API.

Understanding transformer behavior requires a measurable training system, not a chat interface wrapped around someone else's model.

The challenge

The project had to make every core mechanism inspectable: UTF-8-safe byte-level BPE, causal masking, multi-head attention, stable optimization, checkpoint recovery, controlled sampling, and exact validation.

Training pipeline

raw text -> BPE tokenizer -> uint16 token files
         -> random windows -> GPT forward pass
         -> cross-entropy loss -> AdamW update

Checkpoints store the model configuration that created them, so loading does not depend on an external file remaining unchanged.

Verification

  • 32 tests cover tokenizer round trips, causal-mask behavior, manual and fused attention agreement, checkpoint equivalence, and training-loss reduction.
  • Manual attention and PyTorch fused attention are compared numerically before throughput is benchmarked.
  • Training detects divergence, clips gradients, schedules learning rate, and keeps both best and latest checkpoints.

Measured result

The 859K-parameter configuration reached 17.93 validation perplexity in 134.8 seconds. Fused attention ran 2.30x faster than the explicit implementation on an RTX 4070 SUPER.

The 10.8M-parameter model trained 7.7x longer but improved perplexity only 4.3 percent over the tiny model. That result made diminishing returns visible instead of assuming that a larger model was automatically better.
